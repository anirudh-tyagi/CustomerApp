# Customer Map

A small React Native app (bare workflow, **no Expo**) that shows customers from a local
SQLite database on a MapLibre map of India.

- Home screen with tiles (currently one: **Customer Map**, with the customer count).
- Map screen: clustered pins (cluster counts, tap to expand), tap a pin for a bottom sheet with
  name, address and phone, plus **Call**, **Get directions**, **Copy address** and **Share**.
- Works offline for customer data (bundled SQLite DB); the map background needs a network.

| | |
|---|---|
| React Native | 0.81.6 (new architecture, Hermes) |
| Android package / iOS bundle ID | `com.ajantaalgothm.customermap` |
| Map | `@maplibre/maplibre-react-native` 11.5.1, style from OpenFreeMap |
| SQLite | `@op-engineering/op-sqlite` 19.0.3 |
| Navigation | `@react-navigation/native` 7.5.1 + `native-stack` 7.21.0, `react-native-screens` 4.24.0 |
| Clipboard | `@react-native-clipboard/clipboard` 1.16.3 |

All dependency versions are pinned exactly. `react-native-screens` must stay **≤ 4.24.x** on
React Native 0.81 (4.25+ requires RN 0.82 and fails the Android build).

> **Demo data is SYNTHETIC.** Business names, streets and phone numbers are generated by
> `scripts/make_demo_db.py`. Phone numbers are valid-format Indian mobiles and may belong to real
> people: do not place calls with demo data.

## Run on Android (Linux / macOS / Windows)

Prerequisites: Node ≥ 20, JDK 17, Android SDK (platform 36, build-tools 36, NDK 27.1.12297006,
CMake 3.22.1), an emulator or a device with USB debugging.

```bash
cd ~/Projects/CustomerMapApp        # always run npx react-native INSIDE the project
npm ci                              # exact versions from package-lock.json

# Terminal 1 - emulator (host GPU; software rendering hides map labels)
adb start-server
emulator -avd Pixel_API35 -no-metrics -gpu host &
adb devices                         # wait until it says "device"

# Terminal 2 - Metro (debug builds only)
npx react-native start

# Terminal 3 - build + install (first build takes 7-15 min; don't Ctrl+C Gradle)
npx react-native run-android
```

### Release APK

```bash
cd android
./gradlew assembleRelease                                         # all ABIs
./gradlew assembleRelease -PreactNativeArchitectures=x86_64       # emulator-only, faster
adb install -r app/build/outputs/apk/release/app-release.apk
```

The release build is currently signed with the **debug keystore** (template default). Before
publishing, create your own upload keystore and set it in `android/app/build.gradle`
(<https://reactnative.dev/docs/signed-apk-android>). Never commit keystores or passwords.

### Checks

```bash
npm run typecheck     # app code (no Node types) + tests (with Node types)
npx eslint .
npx jest              # unit tests; DB tests run real .db files through node:sqlite
```

Expo check (should print "No Expo" twice):

```bash
ls node_modules | grep -E '^(expo$|expo-|@expo)' || echo "No Expo"
grep -E '"(expo|@expo)' package.json || echo "No Expo in package.json"
```

(Plain `grep -i expo` gives false positives such as "export".)

## Replace the customer database

The app reads **one file**: `data/db/custom/customers.db`. Android bundles it as an APK asset
(`android/app/build.gradle` → `sourceSets.main.assets.srcDirs`), iOS as a bundle resource
(Xcode project). On every app start it is copied into app storage and opened read-only, so a new
file in a new build always takes effect.

1. Make sure your file has this table (extra columns are ignored):

   ```sql
   CREATE TABLE customers (
     id        INTEGER PRIMARY KEY,   -- or TEXT
     name      TEXT NOT NULL,
     address   TEXT,
     phone     TEXT,
     latitude  REAL,                  -- order is (latitude, longitude)
     longitude REAL
   );
   ```

2. Copy it over the bundled file **with the same name** and rebuild:

   ```bash
   cp /path/to/your.db data/db/custom/customers.db
   npx react-native run-android        # or ./gradlew assembleRelease
   ```

No code change is needed. What the app does with your data:

- Rows with missing, non-numeric, `0,0`, swapped or outside-India coordinates
  (lat 6–37.5, lng 68–98) are **skipped and counted** (shown as "N skipped").
- Rows with a missing name, address or phone are **shown**, with "Not available".
- A missing, corrupt or wrong-schema file shows a friendly error with **Retry**; an empty table
  shows "No customers in the database".

Demo / test databases (deterministic, seed 42):

```bash
npm run db:demo     # 500 customers  -> data/db/custom/customers.db
npm run db:stress   # 10,000         -> data/fixtures/customers_10000.db (not committed)
npm run db:bad      # 500 with ~2% bad rows -> data/fixtures/customers_test_bad_rows.db
```

## Change the map style

The style URL is **one constant**: `MAP_STYLE_URL` in `src/config/map.ts`.

- Default: OpenFreeMap "Liberty" (`https://tiles.openfreemap.org/styles/liberty`): free, no API
  key, commercial use allowed, attribution required (MapLibre shows it via the ⓘ button; keep
  `attribution` enabled). Other OpenFreeMap styles: `/styles/bright`, `/styles/positron`.
- Any MapLibre-compatible style URL works. If a provider needs a key, do **not** commit it; load
  it from build config instead.
- Never use `tile.openstreetmap.org` (OSMF tile usage policy forbids app use like this).
- If the style can't be loaded (offline on first run, broken URL), the app switches to a plain
  local fallback style (`FALLBACK_STYLE`) so pins still show, displays a banner, and switches back
  automatically when the style server answers again.
- Cluster count labels use the font `Noto Sans Bold` (`CLUSTER_LABEL_FONT`); a new style must
  serve that font on its glyph server, or change the constant.

### Pin and cluster look

- Single-customer pins are PNG icons in `src/assets/map/` (`customer-pin`, `customer-pin-selected`,
  each with `@2x`/`@3x`), drawn as a MapLibre symbol layer (fast for thousands of pins, works
  offline). They are generated by `scripts/make_map_icons.py` (needs Pillow): change colours or
  sizes there and run `python3 scripts/make_map_icons.py`.
- Cluster colours, size steps and halo live in `src/config/map.ts` (`MAP_COLORS`) and
  `src/screens/MapScreen.tsx` (`CLUSTER_COLOR`, `CLUSTER_RADIUS_EXPR`). Keep white count text
  readable: cluster colours should have ≥ 3:1 contrast against white.

## Troubleshooting (problems hit during development)

| Symptom | Cause / fix |
|---|---|
| `npx` asks "Need to install react-native@0.88.x" | You ran `npx react-native …` **outside** the project folder. Answer no, `cd` into the project. |
| `init` fails / picks wrong version | Pass an **exact** patch version: `npm view react-native@0.81 version`, then `--version 0.81.6`. |
| `installDebug failed on any devices` | No reachable emulator/device, not a code bug. `adb start-server`, start the emulator, wait for `adb devices` → `device`. |
| Map shows no labels / no dashed borders on the emulator | Emulator fell back to software rendering ("Your GPU drivers may have a bug"). Start it with `-gpu host`. |
| Build fails in `:react-native-screens:generateCodegenSchemaFromJavaScript` ("first argument of method showColumn…") | `react-native-screens` too new for RN 0.81. Use 4.24.0. |
| Yellow/red "Open debugger…" / "Cannot connect to Metro" toast | Debug builds only: Metro connection dropped (app reinstalled/backgrounded). Restart Metro or ignore; release builds have no Metro and no toast. |
| `--skip-install false` in `init` skipped the install | The CLI treats the flag as present. Run `npm install` afterwards. |
| Git "Author identity unknown" | `git config user.email …` / `git config user.name …` (repo-local). |
| Map framed too wide on first launch | Fixed: the camera re-fits India after the map loads (`onDidFinishLoadingMap`). |

## Project layout

```
src/
  config/      map.ts (style URL, bounds, clustering, colours), data.ts (DB name, schema), homeTiles.tsx
  database/    connection.ts (op-sqlite), customerRepository.ts, errors.ts
  services/    customerService.ts (shared load), customerActions.ts, mapLogging.ts
  hooks/       useCustomers.ts, useMapConnectivity.ts
  components/  HomeTile, CustomerSheet, MapControls, DataStatusChip, ErrorBoundary, …
  screens/     HomeScreen.tsx, MapScreen.tsx
  navigation/  RootNavigator.tsx, types.ts
  types/, utils/ (validation, format, geojson, logger)
scripts/make_demo_db.py      synthetic demo DB generator (stdlib only)
scripts/make_map_icons.py    generates the map pin icons (Pillow)
src/assets/map/              pin icons used on the map
data/db/custom/customers.db  the bundled DB (replace this file)
data/fixtures/               test databases
```

Logging rule: the app never logs customer names, addresses or phone numbers (only counts,
timings and error types). `src/utils/logger.ts` is the only place that calls `console`.
